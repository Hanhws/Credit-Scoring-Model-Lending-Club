# Lending Club 대출 선별 규칙의 위험조정 성과 연구

시간분할 평가와 통계적 검정을 중심으로

본 프로젝트는 어떤 대출 신청을 승인해야 위험 대비 초과수익이 개선될지를 다룬다. 모든 규칙 및 파라미터는 개발 데이터셋 내에서 확정 및 동결 하였으며, 이후 모델 학습에 사용되지 않은 별도의 테스트 데이터셋에 한 차례 검증을 실시했다. 테스트 데이터셋은 36개월 만기 구조를 가진 2015년 12월부터 2018년 1월까지의 발행분(총 246,009건, 26개 월별 빈티지)으로 구성된다. 

**[→ 최종보고서 전문 읽기](docs/최종보고서.md)**

---

## 최종 규칙

> 신용등급 **A–B**에만 승인하고, 그중 예측 초과수익이 **양(+)** 인 건만 통과시킨다.

| | 자금 집행률 | 평균 초과수익 | Sharpe | Sortino | 손실 빈티지 | 최악의 달 |
|---|---|---|---|---|---|---|
| 전량 투자 (기존 LC 정책) | 100% | 1.05% | 0.34 | 0.52 | 8/26 | −5.7% |
| **최종 규칙 (A–B × 게이트)** | 57% | **1.13%** | **0.84** | **1.87** | **5/26** | **−2.0%** |

위험을 줄이면서 수익도 함께 늘었다. 성과의 원천은 **승인률을 일치시킨 무작위 대조군**(Sharpe 0.33)으로 식별했으며, 차이 +0.51은 정상 부트스트랩 기준 p<0.001이다.

## 검증된 연구 성과와 미검증 영역

- **검증됨**

본 연구에서 제시한 A–B 등급 선별 기법은 대조군 샤프 지수를 +0.51(p<0.001)fh 유의미하게 향상시켰다. 또한, 평균 초과수익도 +0.54%p 동시에 높임으로써 위험을 줄이기 위해 수익성을 희생한 것이 아님을 입증한다.

- **검증되지 않음**

첫째, 103회의 다중검정에 대한 편향을 보정한 결과, 샤프 지수의 절대적인 수준에 대한 통계적 유의성은 확보되지 않았다
둘째, 승인율 타이밍 규칙의 성과 기여도는 +0.007 (p=0.737)로 통계적으로 유의미하지 못했다. 이에 따라 해당규칙은 최종 규칙에서 제외 되었다. 그러나 차분 유효 표본 수가 2.11로 통계적 검정력이 낮기 때문에 이는 효과의 부재보단 효과의 미탐지로 해석하는 것이 타당하다.
셋째, 최종 규칙에서 무위험 게이트가 자금의 99.94%를 통과시켜 실질적인 자산 평가 기준은 LC공시 등급에 의존하는 것을 확인할 수 있었다. 다만, 동일한 모형으로 순위를 매길 경우, 무작위 대조군을 2.65 표준편차로 상회하는 것을 볼 수 있었다.

## 연구 설계의 핵심 요소

- **시간 순서 분할.** 무작위 분할 방식은 모델이 해당 시기의 결과도 학습한다. 이는 평가 데이터로 정보가 유입되는 데이터 누수 현상이 발생하게 된다. 동일한 모델, 변수, 규칙에서 분할 방식만 바꾸면 샤프 지수는 0.84에서 1.32로 수치가 과대추정된다. 본 프로젝트에서 이 값은 데이터 누수에 의해 편향된 성능의 상한선으로 규정한다.
- **빈티지 단위 측정.** 개별 차주의 특이위험은 포트폴리오 분산으로 상쇄된다. 투자자가 실질적으로 노출되고 회피 불가능한 위험은 발행 시점에 따른 포트폴리오 전체의 성과 변동이므로, 본 프로젝트에서는 관측 단위를 동일 발행월 묶음(빈티지)으로 설정한다.
- **대조군 설계.** 본 프로젝트에서는 여섯 전략으로 연구를 설계하였으며, 이 전략을 네 개의 핵심 범주(무엇을 고르나 / 얼마나 집행하나 / 달마다 바꾸나 / 어떻게 학습했나)로 구성한다. 이러한 기준에 따라 요인을 한 가지 씩만 변화를 주며 성과에 기여한 원인 요소를 분리하여 본다.

## 저장소 구조

```
├── docs/          최종보고서
├── src/           분석 코드
├── results/       규칙·성과 산출물 (CSV 14개)
├── figures/       보고서 그림 (PNG 9장)
└── data/raw/      원자료 (Lending Club, FRED 국채금리)
```

| 코드 | 역할 |
|---|---|
| [src/split.py](src/split.py) | 학습 파일을 시간순 6:2:2로 분할 |
| [src/model.py](src/model.py) | XGBoost 학습·예측, valid 블록 기준 조기중단 |
| [src/cashflow.py](src/cashflow.py) | 대출별 월 현금흐름 재구성 |
| [src/metrics.py](src/metrics.py) | 빈티지 단위 수익·위험 계산 (현금 레그 포함) |
| [src/rules.py](src/rules.py) | 선별 규칙과 무작위 대조군 |
| [src/timing.py](src/timing.py) | 신청자 풀 구성 → 승인률 다이얼 (미채택된 실험) |
| [src/inference.py](src/inference.py) | 정상 부트스트랩, HAC 검정, 유효표본수, PSR·DSR |
| [src/pipeline.py](src/pipeline.py) | 개발과 최종 평가의 분리, 대조군 구성 |
| [src/figures.py](src/figures.py) | 보고서 그림 9장 |
| [src/check_report.py](src/check_report.py) | 보고서 마크다운의 렌더링·참조 오류 검사 |

## 재현 방법

`data/raw/`에 원자료를 두고 저장소 루트에서 실행한다.

```bash
# 1단계 개발 + 2단계 최종 평가 (results/ 에 CSV 저장)
python -m src.pipeline

# 보고서의 모든 그림 생성 (figures/ 에 PNG 저장)
python -m src.figures
```

개발과 평가의 분리는 코드 구조로 강제된다. `pipeline.develop()`은 개발용 파일만 적재하여 규칙 일체를 결정·동결한 뒤 반환하고, 최종 평가 단계는 동결된 규칙을 수정 없이 적용한다.
